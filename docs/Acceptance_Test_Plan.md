# Acceptance Test Plan

## 1. 目的

本文件定義未來 AI Agent 開發完成時的最低驗收，不代表目前功能已實作。

## 2. 財務核心

| ID | 情境 | 預期 |
|---|---|---|
| FIN-001 | 貸款同時含本金與利息 | 本金只進現金流／負債，利息進損益 |
| FIN-002 | 年繳 PMS 費 | 付款月現金流全額，管理損益按服務月攤提 |
| FIN-003 | 查看食材成本率 19.1% | 可下鑽至細項、供應商與交易，合計回到 19.1% |
| FIN-004 | 訂金與現場尾款 | 關聯同一訂單，現金流依付款日，收入不重複 |
| FIN-005 | 同一匯入檔重跑 | 不重複建立交易 |
| FIN-006 | 入住日已到、未取消且 PMS 無尾款 | 建立推定已收，不進正式現金流 |
| FIN-007 | 接待確認尾款金額與付款方式 | 推定轉確認並建立一次正式付款事件 |
| FIN-008 | 推定後取消或退款 | 撤銷推定並轉人工處理，不自行反向入帳 |

## 3. OwlNest

## 4. ChatGPT Actions

| ID | 情境 | 預期 |
|---|---|---|
| GPT-001 | 手機查今日入住 | 顯示資料更新時間與完整性 |

| MEAL-002 | 4 個早餐日 | 4 日餐點不重複 |
| MEAL-003 | 超過 4 個早餐日 | 提示餐點不足，輪替但不連續重複 |
| MEAL-004 | 選擇不用餐 | 人數為 0，無餐點與備料 |
| MEAL-005 | 快速新增未設定備料餐點 | 可選用，但備料表顯示缺漏 |

| MEAL-010 | 電話或 LINE 二訪訂房 | 接待人員手動標記二訪後可選不同餐點；系統不做跨訂單自動辨識 |

| MEAL-013 | 管理者修改餐點配方 | 建立新版本，歷史備料表內容不變 |
| MEAL-014 | 停用餐點或備料項目 | 新訂單不再提供選擇，歷史紀錄仍可查詢 |

## 8. 上線門檻

- 所有高風險及安全測試通過。
- OwlNest 唯讀性由操作紀錄確認。
- 至少使用遮蔽測試資料完成一週平行運行。
- 正式通知先在測試群組驗證，再切換工作群組。
- HomeKit 每條規則逐一人工驗證，預設停用後再核准啟用。
- 備份還原及停用整套 Agent 的緊急程序完成演練。
