# 2026 原始財務活頁簿評估

## 1. 評估範圍

- 來源檔：`2026財務報表.xlsx`
- 評估日期：2026-07-24
- 工作表：月報202601～月報202606
- 評估目的：確認原始資料能否轉入 AI CFO V1 的單一交易模型

來源檔僅作為資料盤點，不直接提交至 Git，以降低銀行流水、姓名及其他敏感資訊外洩風險。

## 2. 結論

原始資料足以開始建立 AI CFO V1，但不能直接把現有「總支出」與「淨值」當作正式損益。

主要原因：

1. 每月貸款／分期 NT$61,000 全數列入支出；Loan A 的 2026-05～06、Loan B 的 2026-05～07 已取得實際拆分，其餘期間仍待補。
2. 「其他支出」混合食材、房務耗材、設備、家具、訂閱、平台手續費與稅費。
3. 5 月起其他支出由三欄改為五欄，結構不一致。
4. 銀行流水與手工收入／支出同時存在，匯入時需要防止重複。
5. 「總資產」公式不是標準資產負債表，也不是可靠現金餘額。

建議先進行資料標準化，再產生管理損益與現金流。

## 4. 現有結構

每張月報包含四種不同資料：

1. 頂端月度摘要。
2. 手工整理的住宿收入。
3. 固定支出及貸款／分期。
4. 其他支出與銀行流水。

這四種資料混在同一工作表，造成：

- 同一筆交易可能同時出現在銀行流水及手工區。
- 不同月份的欄位位置不同。
- 公式須按每月實際列數手工調整。
- 支出分類過粗，無法產生食材、房務或設備分析。
- 原始格式延伸至第 1,000 列，實際資料只在前約 120 列，增加維護負擔。

## 5. 公式評估

現有公式沒有發現 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?` 或 `#N/A`。

但是計算口徑存在以下問題：

### 5.1 淨值不是損益

```text
淨值 = 總收入 -（固定支出 + 貸款／分期 + 其他支出）
```

貸款本金不應列入損益費用。必須先拆分：

- 貸款本金：融資現金流。
- 貸款利息：財務費用。

### 5.2 總資產口徑不完整

現有總資產公式以固定位置的帳戶數字加總，未建立完整帳戶主檔、期初餘額或跨月現金調節。因此此欄不得作為正式資產或現金餘額。

### 5.3 5 月起欄位改版

- 1～4 月其他支出主要使用日期、說明、金額三欄。
- 5～6 月改為消費日期、商家／通路、主類別、品項描述、金額五欄。

5 月與 6 月仍保留未連至頂端摘要的舊式合計公式，顯示模板已演變但未完整清理。

## 7. 匯入策略

### 7.1 建議來源優先順序

1. 手工收入區：作為住宿收入及房號的主要來源。
2. 固定支出與貸款區：作為固定支出排程的主要來源。
3. 其他支出區：作為採購與費用的主要來源。
4. 銀行流水：用於對帳及補漏，不直接全部匯入為新交易。

### 7.2 防重欄位

匯入時建立：

- 原始工作表
- 原始列號
- 來源區塊
- 交易日期
- 金額
- 原始說明
- 匯入批次
- 對帳狀態

疑似重複只能標記，不能自動刪除。

線上訂金與現場尾款若可識別為同一訂房，必須共用訂房參考碼，並分別標記 `deposit` 與 `balance`。兩筆都進入現金流，但住宿收入只依收入認列規則計入一次完整房費。

訂金比例、尾款條件與取消政策不由 AI CFO 推算。未來以 PMS／平台資料為權威來源；歷史 Excel 只匯入實際已發生的收款與退款。

### 7.3 日期處理

原始 Excel 日期以序號儲存，例如 `46024`。匯入時轉為真正日期值並以 `yyyy-mm-dd` 顯示。

### 7.4 房號處理

房號 201、202、203、204、301、302、303 一律以文字儲存。若一筆收入包含多間房，V1 可：

- 暫存多房標籤；或
- 依可取得金額拆成多筆。

拆分規則待確認，不應自行平均。

## 8. 資料品質風險

| 風險 | 等級 | 處理 |
|---|---|---|
| 貸款本金與利息未完整拆分 | 高 | 兩筆貸款部分月份已取得；補齊其餘月份 |
| 銀行流水與手工紀錄重複 | 高 | 匯入後人工對帳 |
| 設備與營運支出混合 | 高 | 建立待資產化狀態 |
| 原始公共營運支出混在其他支出 | 中 | 匯入時改列公共營運 |
| 收入來源未完整標記 | 中 | 匯入時補 Booking／官網等來源 |
| 混合採購一筆含多類 | 中 | 允許拆分或標記主要用途 |
| 部分日期／說明缺漏 | 中 | 進入待確認佇列 |
| 敏感銀行資料存在原檔 | 高 | 不提交 Git；AI 前去識別化 |
