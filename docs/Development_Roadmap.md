# Development Roadmap

## 1. 執行策略

採規格驅動、短週期交付。每個里程碑都必須有可驗收成果，不以頁數或文件數作為完成標準。

## 2. Milestone 0：規格基線

成果：

- 本批 Markdown 規格。
- 已知假設與待確認清單。
- 初版科目與資料模型。
- AI 開發交接、OwlNest、ChatGPT Actions、LINE、HomeKit 與驗收規格。

完成條件：

- 文件連結有效。
- V1、Phase 2 與 PMS 後範圍清楚。
- 主要財務規則無互相衝突。

## 3. Milestone 1：資料核心

工作：

1. 確認帳戶、付款方式及支出細項。
2. 建立科目表與主檔。
3. 建立單一交易資料表。
4. 建立匯入欄位映射及驗證。
5. 匯入 2026-01 至 2026-06 歷史資料。

驗收：

- 每筆歷史交易可追溯至來源。
- 待分類清單可查看與修正。
- 2026-07 至 2026-12 可新增資料。
- 重複偵測與匯入報告可用。

## 4. Milestone 2：財務報表

工作：

- 每月損益。
- 現金流摘要。
- 年度彙總。
- 月結與重開流程。
- 會計匯出第一版。

驗收：

- 測試資料結果符合 Business Rules。
- 貸款本金不進入損益。
- 報表可下鑽至交易。
- 未提供期初餘額時有警示。

## 5. Milestone 3：Dashboard

工作：

- KPI 卡。
- 12 月趨勢。
- 收入來源及成本結構。
- 資料品質與待辦警示。
- 列印／匯出格式。

驗收：

- 所有 KPI 與報表一致。
- 未來月份不被誤判為衰退。
- ADR、RevPAR、入住率顯示為待 PMS 整合。

## 6. Milestone 4：AI CFO V1

工作：

- 建立確定性分析資料包。
- 實作月報輸出結構。
- 建立安全與品質檢查。
- 以 2026 歷史資料試跑並人工覆核。

驗收：

- 不捏造原因。
- 每個數字可追溯。
- 缺資料時降低信心。
- 建議具體、限三項且可追蹤。

## 7. Milestone 5：營運化

工作：

- 備份與還原。
- 操作說明。
- 關帳 SOP。
- 錯誤處理與資料更正。
- GitHub 發布與版本標記。

## 8. Phase 2

- 固定資產與折舊。
- 固定資產清冊由使用者盤點後匯入。
- 訂閱、年繳費用攤提及貸款排程。
- 預算 vs 實際。
- 現金流預測。
- PDF 月報。
- 採購自然語言輸入。

## 9. Milestone 6：LINE 行動入口

- 建立 LINE Official Account 與 Messaging API Channel。
- 建立 HTTPS webhook、簽章驗證、事件去重及非同步處理。
- 支援管理者私訊與授權工作群組。
- 支援「記錄採購」「查今天入住」「查明天早餐」「確認任務」等指令。
- 支援新訂單、取消、入住前及用餐提醒。

LINE Notify 已於 2025-03-31 終止，本專案使用 LINE Messaging API。

## 10. Milestone 7：ChatGPT 手機管理介面

- 建立私人 Custom GPT，僅供授權管理者使用。
- 建立 OpenAPI Action Schema 與 HTTPS API。
- 實作今日入住、用餐需求、財務摘要及採購草稿工具。
- 寫入、異動及群組通知採草稿／確認兩階段。
- 所有 Action 記錄使用者、時間、輸入、結果與核准狀態。

Custom GPT 在網頁版建立，但可由 ChatGPT 手機 App 使用。Apps SDK／MCP 行動版成熟後，再評估切換。

## 11. Milestone 8：PMS 瀏覽器整合

- 建立唯讀 PMS 訂單、付款及狀態事件匯入。
- 以瀏覽器自動化擷取訂單列表與詳情；優先使用穩定欄位、可存取的下載功能或頁面資料。
- 登入狀態與 Cookie 只存本機私有目錄，不提交 Git。
- 畫面結構變更、登入失效或 CAPTCHA 發生時停止匯入並通知管理者，不嘗試繞過安全機制。
- 以來源事件識別碼及版本防止重複入帳。
- 日房況、訂單與房費收入。
- ADR、入住率、RevPAR。
- 房型／房號收益。
- 取消、no-show、停售房規則。

AI CFO 不回寫訂金比例、尾款或取消政策至 PMS。

## 12. Milestone 9：方糖民宿營運 Agent

- 統一訂單、住客、住宿、餐飲需求、採購、任務、通知及財務事件。
- 依角色產生今日工作摘要、入住清單與早餐準備清單。
- AI 僅讀取去識別化或最少必要資料；完整敏感資料由規則引擎及權限層保護。
- 支援備份、稽核軌跡、失敗重試、健康檢查與停機通知。

完整設計見 [Operations Agent Architecture](Operations_Agent_Architecture.md)。

## 13. 建議 Git 工作方式

- `main`：可交付版本。
- `feature/<topic>`：單一功能或文件變更。
- Pull Request 必須包含變更摘要、驗證結果及規格影響。
- 每個里程碑完成後建立版本標籤。

建議標籤：

```text
v0.1.0-spec-baseline
v0.2.0-data-core
v0.3.0-financial-reports
v0.4.0-dashboard
v1.0.0-ai-cfo
```

## 14. 規劃完成後的開發順序

目前不實作。交給 AI 開發時依下列順序執行：

1. 完成財務資料覆核、帳戶期初餘額與年繳費用服務期間。
2. 建立本機資料庫、migration、稽核及財務引擎。
3. 以遮蔽截圖與最低權限測試帳號完成 OwlNest 唯讀探索。
4. 建立 OwlNest Collector，先平行運行但不觸發正式通知。
5. 建立 LINE Messaging API 測試群組及 HTTPS webhook。
6. 建立 Actions API，再於網頁版設定私人 GPT，使用手機驗證。
7. 建立確定性規則引擎與通知矩陣。
8. 完成 HomeKit 設備／Shortcut 清冊，逐條啟用低風險規則。
9. 完成一週平行運行、備份還原與停機演練後才正式上線。

工作包、前置資料與交付門檻見 [AI Development Handoff](AI_Development_Handoff.md)。
