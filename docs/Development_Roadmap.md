# Development Roadmap

## 1. 執行策略

採規格驅動、短週期交付。每個里程碑都必須有可驗收成果，不以頁數或文件數作為完成標準。

## 2. Milestone 0：規格基線

成果：

- 本批 Markdown 規格。
- 已知假設與待確認清單。
- 初版科目與資料模型。

完成條件：

- 文件連結有效。
- V1、Phase 2 與 PMS 後範圍清楚。
- 主要財務規則無互相衝突。

## 3. Milestone 1：資料核心

工作：

1. 確認帳戶、付款方式及支出細項。
2. 建立科目表與主檔。
3. 建立單一交易資料表。
4. 建立匯入欄位映射及驗證。
5. 匯入 2026-01 至 2026-06 歷史資料。

驗收：

- 每筆歷史交易可追溯至來源。
- 待分類清單可查看與修正。
- 2026-07 至 2026-12 可新增資料。
- 重複偵測與匯入報告可用。

## 4. Milestone 2：財務報表

工作：

- 每月損益。
- 現金流摘要。
- 年度彙總。
- 月結與重開流程。
- 會計匯出第一版。

驗收：

- 測試資料結果符合 Business Rules。
- 貸款本金不進入損益。
- 報表可下鑽至交易。
- 未提供期初餘額時有警示。

## 5. Milestone 3：Dashboard

工作：

- KPI 卡。
- 12 月趨勢。
- 收入來源及成本結構。
- 資料品質與待辦警示。
- 列印／匯出格式。

驗收：

- 所有 KPI 與報表一致。
- 未來月份不被誤判為衰退。
- ADR、RevPAR、入住率顯示為待 PMS 整合。

## 6. Milestone 4：AI CFO V1

工作：

- 建立確定性分析資料包。
- 實作月報輸出結構。
- 建立安全與品質檢查。
- 以 2026 歷史資料試跑並人工覆核。

驗收：

- 不捏造原因。
- 每個數字可追溯。
- 缺資料時降低信心。
- 建議具體、限三項且可追蹤。

## 7. Milestone 5：營運化

工作：

- 備份與還原。
- 操作說明。
- 關帳 SOP。
- 錯誤處理與資料更正。
- GitHub 發布與版本標記。

## 8. Phase 2

- 固定資產與折舊。
- 訂閱及貸款排程。
- 預算 vs 實際。
- 現金流預測。
- PDF 月報。
- LINE 或其他通知。

## 9. PMS 整合階段

- 日房況、訂單與房費收入。
- ADR、入住率、RevPAR。
- 房型／房號收益。
- 取消、no-show、停售房規則。

## 10. 建議 Git 工作方式

- `main`：可交付版本。
- `feature/<topic>`：單一功能或文件變更。
- Pull Request 必須包含變更摘要、驗證結果及規格影響。
- 每個里程碑完成後建立版本標籤。

建議標籤：

```text
v0.1.0-spec-baseline
v0.2.0-data-core
v0.3.0-financial-reports
v0.4.0-dashboard
v1.0.0-ai-cfo
```

## 11. 立即下一步

1. 回答所有高優先 TBC：帳戶、付款方式、公用營運分類、貸款拆分、期初餘額。
2. 提供或整理 2026-01 至 2026-06 原始 Excel。
3. 產出正式 Chart of Accounts。
4. 建立 Excel V2 可操作原型。
5. 用一個月份做端到端驗收，再匯入其餘月份。
