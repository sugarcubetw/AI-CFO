# OwlNest PMS Integration

## 1. 狀態與邊界

- 系統商：OwlTing。
- 產品：OwlNest 訂房管理系統。
- 本案目前未取得可用 API 文件。
- 本文件只定義規劃；尚未登入、擷取或實作。
- PMS 是訂單及付款狀態的來源，本系統 V1 只讀，不回寫房價、房量、訂金或取消規則。

## 2. 擷取優先序

1. OwlNest 內建 CSV、Excel、列印或銷售報表。
2. 已登入頁面可穩定取得的結構化資料。
3. 訂單列表加訂單詳情的瀏覽器自動化。
4. 不使用螢幕座標或 OCR 作為常態方案；只能列為人工輔助與最後手段。

任何方案開始前均須確認帳戶權限與服務條款。不得繞過 CAPTCHA、2FA 或存取控制。

## 3. 探索階段

### 3.1 所需畫面

- 登入後首頁。
- 訂單列表、分頁及篩選。
- 訂單詳情。
- 入住／退房、房型／房號及人數。
- 訂金、尾款、退款及付款狀態。
- 住客備註、用餐時間與飲食需求。
- 取消及異動紀錄。
- 匯出、列印及報表功能。

所有截圖須遮蔽姓名、電話、Email、訂單編號、付款資料及登入資訊。

### 3.2 探索輸出

- 欄位對照表。
- 頁面／資料來源穩定性評分。
- 登入生命週期與人工介入點。
- 同一訂單的建立、異動、取消、付款範例。
- 可重複的唯讀測試腳本。
- 系統商條款與允許範圍紀錄。

## 4. 標準事件

| 事件 | 必要欄位 |
|---|---|
| `reservation.created` | PMS 訂單碼、來源、入住／退房、房型、人數、版本 |
| `reservation.updated` | 訂單碼、變更欄位、前後值、版本 |
| `reservation.cancelled` | 訂單碼、取消時間、狀態、版本 |
| `payment.recorded` | 訂單碼、付款階段、金額、付款日、方法 |
| `payment.refunded` | 訂單碼、退款金額、退款日、原付款參考 |
| `stay.checked_in` | 訂單碼、房號、實際入住時間 |
| `stay.checked_out` | 訂單碼、實際退房時間 |
| `meal_requirement.updated` | 訂單碼、日期、時段、人數、禁忌版本 |

訂金與現場尾款必須以相同 `reservation_external_id` 關聯。付款日期用於現金流；住宿收入認列日期依 [Business Rules](Business_Rules.md)。

若 OwlNest 未登錄現場尾款，入住日已到且訂單未取消時，本機營運層可建立 `balance.presumed_collected`，但不得把它當成 PMS 原始事件或正式現金交易。接待確認後另建 `payment.confirmed`；本系統不回寫 OwlNest。

## 5. 同步演算法

1. 取得同步鎖，避免兩個程序同時執行。
2. 驗證登入狀態與頁面指紋。
3. 依更新時間視窗抓取列表；時間範圍需重疊，避免邊界漏單。
4. 保存原始快照及雜湊；快照加密且限制存取。
5. 轉成標準資料並執行欄位驗證。
6. 以 `source_system + external_id + source_version/event_hash` 去重。
7. 比較前一版本並產生事件。
8. 事件寫入成功後才推進同步游標。
9. 由規則引擎產生任務及通知。
10. 失敗時保留游標、記錄錯誤並通知，不猜測缺漏欄位。

## 6. 登入與憑證

- 首選人工登入後使用專屬瀏覽器設定檔維持 session。
- 密碼、Cookie 及 session 資料只存於本機受限目錄。
- 登入過期時轉為 `AUTH_REQUIRED`，要求管理者介入。
- 遇 2FA/CAPTCHA 時停止，不自動破解。
- Collector 使用專用最低權限 OwlNest 帳號；若系統支援，禁止編輯及退款權限。

## 7. 健康狀態

| 狀態 | 行為 |
|---|---|
| `HEALTHY` | 正常同步 |
| `AUTH_REQUIRED` | 停止抓取並通知人工登入 |
| `PAGE_CHANGED` | 保存診斷資訊，停止該資料流 |
| `VALIDATION_FAILED` | 隔離該批資料，不推送營運動作 |
| `RATE_LIMITED` | 延後重試，不高頻刷新 |
| `PARTIAL` | 明示資料不完整，禁止形成完整入住清單 |

## 8. 驗收

- 重複擷取相同訂單不會建立重複事件或財務交易。
- 訂單異動能指出欄位前後差異。
- 取消、退款、訂金及尾款不互相覆蓋。
- 登入失效、欄位消失與分頁失敗均能停機並通知。
- Collector 全程不修改 PMS。
- 原始快照、標準資料、事件及通知可相互追溯。
